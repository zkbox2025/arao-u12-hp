F09. Platformサポート管理画面
目的
DEVELOPERまたはSUPPORTが全クラブのSupportReportを管理できるようにします。
実装範囲
1. Platform専用ログイン導線を確定する。
   - 推奨：/platform-loginを追加し、クラブMembershipが0件でもPlatformAdminならログインできるようにする。
2. requirePlatformAdmin()の存在しないredirect先を修正する。
3. /platform/supportへ専用layoutを追加し、クラブ用フッターを表示しない。
4. 全クラブのSupportReportを新着順で表示する。
5. クラブ、status、categoryで絞り込めるようにする。
6. 内容全文を安全に表示する。
7. statusをOPEN / IN_PROGRESS / ON_HOLD / RESOLVEDで変更する。
8. 内部メモを更新する。
9. handledByPlatformAdminId、statusChangedAt、resolvedAtを正しく更新する。
10. PlatformAdminがクラブのOWNER権限を自動的に得ないことを維持する。
受入条件
- isActive = falseのPlatformAdminは入れない。
- 一般クラブ会員はURL直打ち・Action直呼びの両方で拒否される。
- RESOLVEDへ変更するとresolvedAtが入り、戻すとnullになる。
- Platform画面からイベント・お知らせ等のクラブデータへ越権アクセスできない。
理解する重要箇所
- PlatformAdminとClubMembershipが別権限であること
- サポート担当者が全クラブ報告を見られる例外の境界
- Platform専用layoutとクラブlayoutを分ける理由
