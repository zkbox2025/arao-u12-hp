F06. /welcome・招待承諾
目的
招待された利用者が本人確認後にパスワードを設定し、招待を一回だけ承諾できるようにします。
実装範囲
1. Auth confirm Routeでinviteを扱い、Supabaseセッション確立後に/welcomeへ安全に遷移する。
2. URLのraw tokenを検証後に除去し、必要なら短時間・HttpOnly・SameSite cookieへ交換する。
3. /welcomeで次を確認する。
   - token hash一致
   - 未使用
   - 有効期限内
   - Invitationが承諾可能状態
   - MembershipがINVITED
   - ログイン中Auth userと招待emailが一致
4. パスワード8文字以上・英数字・確認一致を検証する。
5. Supabase Authのパスワード更新後、DB承諾処理を一回限りで実行する。
6. InvitationをACCEPTED、acceptedAt=nowへ更新する。
7. MembershipをINVITED -> ACTIVEへ更新する。
8. 二重送信・二重承諾は条件付き更新で拒否する。
9. 失効、取消、email不一致、すでに承諾済みを区別して安全な案内を表示する。
10. 完了後は対象クラブへ遷移する。
受入条件
- 有効な招待だけ承諾できる。
- tokenだけを別Authユーザーが取得しても承諾できない。
- 同時に2回送信しても一度しかACTIVEにならない。
- 承諾後のtokenは再利用できない。
- 複数クラブ所属になる場合も既存所属を壊さない。
理解する重要箇所
- Supabaseの認証確認とアプリDBの招待承諾が別処理であること
- token、Auth email、Invitation emailの三者を照合する理由
- 条件付き更新による一回限り保証
