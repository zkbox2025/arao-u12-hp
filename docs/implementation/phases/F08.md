F08. 不具合・サポート報告送信
目的
全ACTIVE会員がマイページから問い合わせを送り、DBを正本として受付を残せるようにします。
実装範囲
1. マイページへcategoryとmessageのフォームを追加する。
2. requireActiveClubMembership()をAction内でも実行する。
3. messageはtrimし、最大2000文字とする。
4. clubId、membershipId、reporter情報をサーバー側から取得する。
5. pageUrlをallowlist方式でsanitizeする。
6. userAgentをサーバー側で取得し、長さを制限する。
7. SupportReportへ報告時点の氏名・email・roleをsnapshot保存する。
8. DB保存後に共通Resendで運営者へ通知する。
9. メール失敗時も受付成功とし、notifyErrorと安全なログを残す。
10. 成功トーストとフォームresetを実装する。
受入条件
- OWNER以外も送信できる。
- hiddenのclubId、membershipId、reporterEmailを信用しない。
- メール障害時もDBに報告が残り、利用者には受付成功を表示する。
- URLへtokenや秘密情報が含まれても保存前に除去される。
理解する重要箇所
- DB保存を正式受付、メールを補助通知とする理由
- 報告者snapshotを残す理由
- client入力とserver取得データの境界

粒度1の仕様・入力・結果契約
- 全ACTIVE会員は、CLUB_APPを利用できるプラン内のOWNER・COACH・OFFICER・MEMBER全員を指す。
  現在はSTANDARDが対象であり、STARTER・PROへ利用範囲を広げない。
- categoryはBUG・QUESTION・REQUEST・OTHERの4種。初期値はBUG、messageは空文字とする。
  FormDataのcategory・messageは各1個の文字列を要求し、欠損・File・重複・不正値を拒否する。
- messageはtrim後の空欄を拒否し、JavaScriptのlengthで2000文字以内とする。
  表示用valuesを2000文字へ制限しても、保存前の検証は切り詰め前の入力に対して行う。
- 入力の成功値とActionStateのvaluesはcategory・messageだけを持つ。
  clubId・membershipId・reporter情報・status・通知結果・任意の戻り先を入力からコピーしない。
- pageUrlは送信時のマイページを示す相対パスとする。直前ページの履歴管理は追加しない。
  後続Actionが認可済みslugから `/club/{encodedSlug}/account` を構築してallowlistを確認する。
  クライアントのpageUrl・Referer・Hostを保存先の根拠にせず、query・fragmentは保存しない。
  別クラブ・認証・招待・外部URL等は許可せず、許可できないmetadataはnullとする。
- userAgentは後続Actionがawait headers()から取得し、制御文字除去・trim後に512文字へ制限する。
  欠損・空はnullとする。UAは偽装可能な補助情報であり、認証・認可には利用しない。
- reporterName・reporterEmailは保存時のAppUser、reporterRoleは最新Membershipからsnapshot保存する。
  name・emailのnullを許可し、AuthとAppUserのemailを同期・修復しない。
- 新規SupportReportはOPENで作成する。既存status enumや管理用列は変更しない。
- DB受付内部はCREATED・ALREADY_ACCEPTED・拒否・失敗を区別する。
  検証済みrequestIdを既存SupportReport.idへ使用する重複対策と、本人・内容の照合は後続Repositoryが行う。
  requestIdの形式一致だけでは認証・認可や一回限り保存を保証しない。
- 通知は固定結果と固定notifyErrorコードだけを扱い、SDK/DB例外の原文・本文・snapshotをログへ渡さない。
  通知の設定不足・失敗・結果不明や通知結果保存の失敗でも、保存済みの受付成功を維持する。
- 成功はActionStateで返し、新requestIdのkeyで報告フォーム内側だけをresetして固定トーストを表示する。
  ページ全体のredirectで既存の氏名・Childフォームの未保存入力を消さない。
- 粒度1の純粋関数と型は、認可・snapshot取得・DB保存・通知・画面resetを実行しない。
  Repository、通知adapter、Service、Action、Pageへの接続は後続粒度で実装する。
