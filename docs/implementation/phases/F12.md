F12. DB統合・E2E・テナント越境・障害テスト
目的
「画面で動く」だけでなく、MVP 1.0の完成条件を自動確認できる状態にします。
実装範囲
1. DB integration test基盤を追加する。
2. Playwright等のE2E基盤を追加する。
3. テスト専用seedで次を作る。
   - テナントA OWNER / COACH / OFFICER / MEMBER
   - テナントB OWNER / MEMBER
   - 複数クラブ所属ユーザー
   - PlatformAdmin
4. 認証・メール・LINE・Storageをテスト環境で安全にstubまたはローカルサービスへ接続する。
5. migrationを空DBへ適用するテストを作る。
6. 既存データがあるDBへのmigration適用も確認する。
7. tenant越境テストを実装する。
   - clubSlug
   - eventId
   - noticeId
   - attachmentId
   - membershipId
   - childId
   - targetId
   - invitation token
   - webhookKey
   - hidden clubId改ざん
8. role越権テストを実装する。
9. 最後のOWNER、招待二重承諾、LINE並列送信、Storage lease復旧をテストする。
10. Resend・LINE・Storage失敗時のDB状態をテストする。
11. package scriptsを追加する。
    - test:integration
    - test:e2e
    - verify:mvp
12. verify:mvpで環境変数、Prisma、migration、lint、typecheck、unit、integration、E2E、buildを順に確認する。
受入条件
- MVP完成条件の重要項目が手作業メモではなく自動テストになっている。
- テナントAからテナントBの全主要IDへアクセスできない。
- MEMBERから管理Actionを直接呼んでも拒否される。
- STARTERはアプリ利用不可、STANDARDは利用可、PROは保留のまま利用不可。
- 全チェックとproduction buildが成功する。
理解する重要箇所
- unit、DB integration、E2Eで何を分担するか
- 正常系より越境・並列・途中失敗テストが重要な箇所
- 外部サービスを本番へ送信せずにテストする方法
