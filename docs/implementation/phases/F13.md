F13. 本番初期化・リリース準備・本番確認
目的
ローカルで完成したアプリを、既存HPを壊さずにARAO U-12向けMVP 1.0として公開します。
実装・運用範囲
1. 本番DBバックアップを取得する。
   - Supabase Proの日次バックアップを利用する（PITRは導入しない）。利用者が、管理画面で、Pro・日次バックアップの一覧
     （2026年11月4日〜10日UTCの7件、最新はUTC 11月10日 16:25:47）を確認した（2026-11-11の報告）。
     復元の操作と、別環境での復元確認は未実施で、復元可能なことは実証されていない。
   - 日次バックアップとは別に、本番migration直前の手動バックアップと、別の検証環境での復元確認を行う。
   - Storageのファイル本体など、DBバックアップの対象外のものは、別に保全・復元する。
   - バックアップ時点より後のDB書込みは、復元で失われる可能性がある。
   - 手順は[本番migration手順書]を参照する。
2. migration適用手順とrollback判断基準を文書化する。
3. 本番用の安全なアプリ初期化スクリプトを作る。
   - ARAOのClub
   - 現管理者のAppUser
   - OWNER / ACTIVE / canManageWebsite = trueのMembership
   - PlatformAdmin
   - 必要なClubEmailSetting
   - 暗号化済みClubLineSetting
4. 本番Auth user.id・emailとの一致を確認してからupsertする。
5. アプリ公開前はARAOをSTARTER、公開時にSTANDARDへ切り替える運用を確認する。
6. 非公開Storage bucketと制限を本番で確認する。
7. Vercel環境変数を一覧で確認する。
8. Cronが認証付きで実行されることを確認する。
9. LINE DevelopersのWebhook URLをクラブ別URLへ切り替える。
10. 招待・Support通知のResend送信元を確認する。
11. OWNER、MEMBER、PlatformAdminで本番smoke testを行う。
12. 既存HP管理画面が従来どおり動くことを確認する。
13. DB方式のHP管理認可へはまだ切り替えない。
14. 安定確認後にMVP 1.0のrelease tagを付ける。
受入条件
- 本番で管理者・会員・Platform管理の主要導線が動く。
- 既存HPに回帰不具合がない。
- Cron、LINE、Resend、Storageの実サービス疎通が確認できる。
- WEBSITE_ADMIN_USER_IDSは引き続き有効で、DB認可への切替は行っていない。
- 障害時にどこまで戻すかが文書化されている。
理解する重要箇所
- ローカルseedと本番初期化を分ける理由
- アプリ公開とHPマルチテナント化が別作業であること
- 本番外部サービスの最小smoke test範囲
